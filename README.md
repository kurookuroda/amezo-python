Origin/Referer の検証は、コメントアウトで無効になっている前提です。

# あめぞう風掲示板 (Python版) の動作説明

## 1. 全体像

**読む側は静的な HTML、書く側だけが CGI** という構成です。投稿があるたびに板の `index.html` を作り直し、閲覧者にはそのファイルをそのまま配信します。

| ファイル | 役割 |
|---|---|
| `setup_expose.py` | 簡易 Web サーバー兼 CGI 実行器。ディレクトリ準備とトンネル公開もする |
| `index.html` | 親ページ。左に板一覧、右に板を並べたフレーム画面 |
| `dai.py` (`/dai.cgi`) | 左側の板一覧と、各板の見出し(HEAD LINE)を出す |
| `amezo.py` (`/amezo.cgi`) | 投稿の受付、スレッドファイルの更新、板の `index.html` の再生成 |
| `admin.py` (`/admin.cgi`) | 管理画面。レスの削除、スレッドの非表示と復元 |
| `style.css`、`header.html` | 共通の見た目と、板の上部(リンク・注意書き・新規投稿フォーム) |

## 2. データファイル

| ファイル | 内容 |
|---|---|
| `blist.txt` | 板の定義。`フォルダ名,背景色,タイトル` の1行1板 |
| `ng.txt` | NG ワード。`ワード,オプション` (なし=削除、`n`=名前、`c`=本文に含まれたら投稿しない) |
| `delpass.txt` | 管理用パスワードのハッシュ (`pbkdf2_sha256$…`)。`amezo.py --make-hash` で作る |
| `global.mem` | 新規スレッド作成の IP 制限用。IP と時刻を 180 秒だけ保持 |
| `admin_fail.mem` | 管理画面のログイン失敗の記録 (IP、回数、時刻) |
| `板/数字.html` | スレッド (数字は作成日時 `yyMMddHHmmss`) |
| `板/x数字.html` | 非表示にしたスレッド |
| `板/o数字.html` | 古くなって退避されたスレッド (過去ログ)。`MAX_THREADS` を超えた分が、先頭に `o` を付けて改名される |
| `板/kako.html` | 過去ログの一覧。新しく退避したときに作り直す |
| `板/index.html`、`index2.html` | 再生成される板の一覧ページ (1ページ目、2ページ目以降) |
| `板/lasttime.txt`、`regen.lock` | 連投制限用の時刻、再生成の排他ロック |

## 3. サーバー (`setup_expose.py`)

**起動時の準備**
- `amezo.py`、`dai.py`、`admin.py` に実行権限を付けます。
- `blist.txt` の各板のフォルダを作成し、`index.html` が無ければ転送ページを置きます。転送先は `../amezo.cgi?folder=板名` です。
- `cloudflared` でトンネルを張り、公開 URL を表示します。

**リクエストの振り分け**
- `/amezo.cgi`、`/amezo.py`、`/dai.cgi`、`/admin.cgi` などは、CGI として実行します。実行できるのは `ALLOWED_CGI` の3つだけです。環境変数 (`REQUEST_METHOD`、`QUERY_STRING`、`REMOTE_ADDR`、`HTTP_*` など) を渡し、標準入力に POST を渡して、30 秒で打ち切ります。POST は 64KB を超えると 413 を返します。
- それ以外は**許可リスト方式の静的配信**です。許可するのは、`/`、`/index.html`、`/style.css`、`blist.txt` にある板の `index.html`、`index2.html`、`数字.html`、過去ログの `o数字.html` と `kako.html` だけです。`delpass.txt` や `x〜.html`、ソースファイルは 404 を返し、ディレクトリの一覧も出しません。

## 4. 画面の構成

- **親ページ** `index.html` が、2つの iframe を並べます。左が `dai.cgi` (幅 220px)、右が `name="naka"` で、最初は `main/` を開きます。幅 700px 未満では、一覧が上、板が下になります。
- **板一覧** `dai.py` は、`<base target="naka">` により、リンクを右フレームで開きます。`blist.txt` の板ごとに、板名リンクと、その板の `index.html` から取り出した見出し (最大 20 行) を並べます。
- **板のページ** は、`header.html` の内容 (板のリンク、注意書き、新規投稿フォーム) の下に、見出し一覧、続けてスレッドの抜粋が並びます。抜粋は、1ページ 20 スレッドで、各スレッドは 1 番のレスと、最後の 7 レスです。

## 5. 投稿の流れ (`amezo.py`)

1. **受け取り**: 送信が 7500 バイト (`MAX_POST_BYTES`) を超える内容と、`CONTENT_LENGTH` が負の値のものは拒否します。フォームの値は、見えない文字を除去し、HTML エスケープし、本文の改行は `<br>` に変えます。
2. **板の判定**: `folder` が無ければ Referer のパスから取り出します。`blist.txt` に無い板、`/` や `..` を含む名前は拒否します。
3. **再読み込み扱い**: 3つの入力欄がすべて空、`name`/`subj`/`comm` が同じ値、または NG ワード (`n`/`c`) に当たった場合は、投稿せず、ページの再生成だけを行います。「次のページ」の操作もこの扱いです。
4. **入力の検査**: 改行 20 個まで、題名 45 文字まで、本文 400 文字まで、メール 50 文字まででエラーにし、投稿者名は 25 文字を超えた分を切り捨てます。文字数は、全角・半角・絵文字を区別せず1文字と数え (`&amp;` などのエスケープも1文字、本文の改行も1文字)、題名と名前は空白を除いた文字数です。上限は `amezo.py` の `SUBJ_MAX`、`NAME_MAX`、`MAIL_MAX`、`COMM_MAX` で変えられます。名前の空白は除去し、`ng.txt` の削除ワードを取り除きます。管理者名「サポート」を名乗る投稿は、`＃サポート` に変えます。
5. **制限**: 同じ板で 5 秒以内の連投は拒否します (`lasttime.txt`)。新規スレッドは、同じ IP から 180 秒に 1 回だけです (`global.mem`)。
6. **書き込み**:
   - 新規スレッドは、`yyMMddHHmmss` のファイルを `O_EXCL` で作ります。重複したら番号を足して、30 回まで試します。
   - 返信は、既存ファイルをロックして、最後のレス番号を数え、直前のレスと名前・本文が同じなら「二重カキコ」で拒否します。
   - 本文の URL はリンクにし、メールアドレスがあれば名前を `mailto:` リンクにします。
7. **再生成と転送**: 板の `index.html` を作り直し、`../板/index.html` に 303 で転送します。右フレームの中で、新しいページが表示されます。

## 6. スレッドファイルの形式

行単位のテキストで、他の処理 (一覧、レス表示、管理画面) が、この形式に頼っています。

- **1 行目**: `<html><head>…<title>題名</title><link …></head><body><dl><dt>1…</dl>`。題名と 1 番のレスが入っています。
- **2 行目以降**: `<dl><dt>番号 投稿者 日時 <dd>本文 </dl>` が、1 レス 1 行で並びます。
- **最終行**: 返信フォームと `</body></html>`。投稿のたびに、この行から上書きされます。

## 7. 板の再生成 (`regen_index`)

- 最近更新されたページは作り直しません (1 ページ目は 5 秒、2 ページ目以降は 10 秒)。
- `regen.lock` で排他制御をします。投稿のときは最大 10 秒待ち、再読み込みのときは、取れなければ作り直しを諦めます。
- 一時ファイルに書き出してから `os.replace` で入れ替えるので、閲覧中に壊れたページが見えることはありません。
- スレッドは、**更新日時の新しい順**に並びます。返信されたスレッドは、先頭に来ます。
- **過去ログ**: `MAX_THREADS` (初期値 200) を超えた古いスレッドは、`数字.html` を `o数字.html` に改名して退避します (0 なら退避しません)。退避が起きると、題名の一覧 `kako.html` を作り直し、板のページに「過去ログ」へのリンクを出します。過去ログへの返信は受け付けず、「過去ログになったため返信できません」と表示します。復元するには、サーバー上で `o` を外して改名します。
- 2 ページ目以降は、`index2.html` を共用して上書きし、`<!-- AMEZO-NEXT 数字 -->` というコメントで、どのページを作ったかを区別します。

## 8. 管理画面 (`admin.py`)

- **認証**: 各画面のフォームにパスワードを持たせ、送信のたびに `delpass.txt` のハッシュと照合します。同じ IP から 5 回失敗すると、15 分間は照合せずに拒否します。クッキーやセッションは使いません。
- **画面**: 板の一覧、スレッドの一覧 (表示中と非表示中)、レスの一覧 (チェックボックス) の順にたどります。
- **操作**:
  - レスの削除: 選んだレスの行を削除します。**1 番は削除できません**。スレッドの更新日時は、残った最後のレスの日時に戻します。
  - 非表示: `数字.html` を `x数字.html` に改名します。復元はその逆です。
- 操作のあとは、板の `index.html` を再生成します。画面には、`Cache-Control: no-store` と noindex を付けています。

## 9. 現在の安全対策と注意点

- **入っているもの**: 静的配信の許可リスト、入力の HTML エスケープ、板名の検証、スレッド作成の `O_EXCL`、`flock` による排他制御、POST のサイズ上限、パスワードのハッシュ化と失敗回数の制限。
- **入っていないもの**: Origin/Referer の検証 (一時的に無効)。他のサイトのフォームから、投稿を送らせることが可能です。管理画面の操作は、パスワードがフォームに入っているので影響しません。
- **IP の判定**: `amezo.py` の `client_ip()` は、接続元が `127.0.0.1` のときだけ、`CF-Connecting-IP` や `X-Forwarded-For` を信用します。プロキシ経由で全員が同じ IP に見えると、IP 制限が、全員に一斉に効くことがあります。

## 10. 使い始める手順

1. `blist.txt`、`header.html`、`style.css`、`index.html`、`dai.py`、`amezo.py`、`admin.py`、`setup_expose.py` を置きます。
2. 管理用パスワードを作り、`delpass.txt` に保存します。
3. `setup_expose.py` を起動し、表示された URL の `/` を開きます。
